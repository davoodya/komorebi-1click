## 4. The one debugging story the next agent must know

A freshly built binary died **before `main`** with `STATUS_CONTROL_C_EXIT`
(0xC000013A): no output, no panic, no crash log, for both debug and release. Cause:
rewriting `build.rs` without keeping its original `tauri_build::build()` call — it
compiles cleanly and produces a dead binary (the context `generate_context!` embeds is
never generated; on Windows the icon resource is not embedded). Removing build.rs
entirely is worse (`OUT_DIR env var is not set`). **Diagnosis recipe**: one
`eprintln!` at the top of `main` distinguishes pre-main death (loader/runtime phase)
from program death; then bisect by reverting to HEAD one file at a time — never
`git stash`, the working tree carries other sessions' work. Full lesson recorded in the
`komorebi-1click-workflow` skill; obey it before touching any build script.

## 5. How to work here (the operating facts that cost time to learn)

- **Gate after every edit batch** (not only at ticket end): `cargo test` ·
  `npx vitest run` · `npx tsc --noEmit` · `npm run check` (svelte-check) ·
  `node tests/check-shipped-text.mjs` · `cargo tauri build --no-bundle -- --locked`.
  Edits made through `execute_code` batches CAN be silently lost when a later assert
  aborts the cell — re-read every file you meant to touch after any AssertionError.
- **Verify a GUI exe through the bridge** with `Start-Process` redirects, never
  `& $exe`; the launch helper is `win-exec.sh` (`ALLOW_WINDOWS=1`). A GUI window
  launched from the bridge renders on another desktop — polling `MainWindowHandle`
  reports a false timeout, which is why the measurement script probes the child
  WebView2 process instead ("runtime-up").
- **Publish/measure recipe**: `Set-Location H:\Repo\komorebi-1click; pwsh -NoProfile
  -File tests\rust-release-measure.ps1` → feed its JSON into
  `tests/rust-release-pins.json` (the ONLY place a rebuild changes; the sandbox
  suite §T13 reads it).
- **Nobody touches the live Komorebi/WHKD/YASB stack from this track** — Windows
  Sandbox or `-DryRun` only (user mandate). Everything unattended runs read-only or
  against the built binary.
- **Test ownership**: the full test pass (visual, scale, clean machine, sandbox,
  elevation relaunch) is Davood's — recorded UNCHECKED in `tests-reminded.md`; an agent
  must not tick them.
- **Working tree hygiene**: `git status` currently shows ~30 foreign entries
  (config/, backups, old installers, `autohotkey/ahk-state.json`, deleted docs…) —
  commit ONLY the files you changed (the ticket/session 15 commit staged exactly 17).
  `.e.txt`/`.o.txt` are bridge probe scratch that WSL cannot delete (Windows-owned) —
  leave them or clean from a Windows shell.
- Commit crews are single-author and linear on `main`; LF→CRLF warnings are normal.
